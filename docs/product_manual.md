# 涅凰智农：硬件接云和报文联调说明

更新：2026-10-02。给硬件研发、现场安装和联调人员使用。

先按下面的顺序走：**设备连云 → 发上行测试包 → 看云端收到什么 → 查看解析 → 发一次下行 → 对照设备回显**。先把收发链路确认好，再验收温度曲线和设备动作。

## 1. 准备好地址和设备信息

请向本次联调负责人拿到后台地址、管理员账号、设备网关名称和采集执行器 ID。账号密码单独交接，不放在报文或截图里。

| 用途 | 入口 |
|---|---|
| 本轮个人测试云的管理后台 | http://43.143.208.153:8080/admin/ |
| 硬件网关 TCP 接入 | `43.143.208.153:8081` |
| 查看收包和打开手动测试窗口 | 后台左侧「原始报文排查」，路由 `/admin/#payload-events` |
| 查看下行命令状态 | 后台左侧「控制日志」，路由 `/admin/#logs` |
| 查看谁提交了操作 | 后台左侧「操作日志」，路由 `/admin/#operation-logs` |
| 在线使用说明 | 后台左侧「帮助中心」，硬件章节 `/admin/#help-center?section=hardware` |

这些地址用于当前测试环境，正式交付地址另行通知。8080 是浏览器后台，8081 是硬件收发口，设备不要把报文发到后台网页端口。

“设备网关”是连云的设备；“采集执行器”是网关下面采温度、接限位或带继电器的节点；“功能点”是平台里对应的温度或控制通道。联调时写清网关、频点和采集执行器 ID，别只报一个 ID。

## 2. 让设备连上云

1. 把设备网关设为 **TCP 客户端**，主动连接上面的 TCP 地址，并保持连接。云端下行会沿这条连接返回。
2. 连接后按已约定的接入名称发送注册内容，例如 ASCII `FP_xxx`；`xxx` 换成双方约定的名称。这是网关注册，不是采集执行器注册。
3. 按硬件已有周期持续发送心跳；本轮接入支持 ASCII `keepalive`。先确认注册、心跳，再发工作数据。
4. 发送原始字节。串口/网络工具输入 Hex 时要选“十六进制发送”，不能把 `7E` 两个文字字符当成字节发送。注册和心跳的 ASCII 文本则按文本发送。
5. 管理员进入「设备管理」（`/admin/#gateways`）确认网关可见、最后上报时间有更新。平台中补建节点或功能点，只是建档，不能代替真实设备接入。

正常表现：TCP 连接保持；后台能找到对应网关和本轮时间的注册/心跳记录。网关在线只说明接入还在，不代表温度已入库，也不代表继电器已经动作。

## 3. 发一个上行包，确认云端收到

**硬件 → 云端**的测试包，从硬件或你们的 TCP 测试工具发；后台「报文调试窗口」用于 **云端 → 硬件**下行，方向别反了。

1. 从本轮客户确认的完整报文中选一帧，保留原始字节、方向和发送时间。优先用 [10/1 客户报文](protocols/mcu0-20261001/README.md) 与 [完整50帧原文](protocols/mcu0-20261001/frames.txt)，不要自己拼未知字段，也不要把其中的下行 ACK 当上行样例。
2. 用同一条已注册的 TCP 连接发出该上行包。
3. 打开「原始报文排查」。来源选「TCP 原始报文」，类型先选「全部类型」，状态选「全部状态」。搜索框写网关名称；时间先选「最近 1 小时」，旧包再扩大范围。
4. 对照「接收时间」「设备网关 / 采集执行器」「连接内消息 ID」和「原始报文」。点击该行右侧放大镜「查看详情」。
5. 详情中核对「TCP 原始 Hex」和你发出的完整字节，再看协议字段、CRC 和业务处理状态。必要时保留原始快照中的方向和采集类型。

正常表现：出现新的对应记录，收到的 Hex 与发送的一致。一次 TCP 收到的字节可能包含半包或多包，所以一条记录不一定就是一条完整业务包。页面标为未完成的半包，不能按完整包判断 CRC 或温度。

## 4. 怎么看温度和解析结果

当前 MCU0 客户样例采用 `7E + LEN + 正文`；完整长度为 LEN 加2。CRC 是报文末尾的两字节校验码，低字节在前，校验正文、不含前面的7E和LEN。只用于核对本轮协议，不拿旧 MCU1 规则替代。

本轮已收到的样例：手动实时包约每4分钟回显；历史温度每5分钟存一组，样例在整点发历史包，出现15组、11组。**不能把旧说明中的“云端每4小时读一次”当本轮操作要求，也不能固定要求每包12组。** 历史序号对应哪几个采样时刻、跨天日期和短历史规则仍需客户确认。

页面里的两个结果要分开看：

- **协议解码**：这串字节能否看懂，例如 CRC、温度、状态和记录组数。
- **业务处理**：这些数据是否已经进入设备当前值、温度历史或控制结果。

客户回复与本地验证确认温度为有符号两字节；本轮实样验证了大端与除以10，未包含负温样例。时间按普通二进制读，例如 `11 39 00` 是17:57:00。平台详情可展示候选解码；真实设备身份、历史日期和跨采集拼包尚未完成生产验收，**不能承诺发包后温度曲线必定更新**。历史包出现也不能直接判当前模式已切为自动。

## 5. 在哪里手动发下行测试报文

准确入口：**左侧「原始报文排查」→ 列表上方、条数旁的「报文调试窗口」**。它不是帮助中心里的按钮，也不是「设备管理」的功能点控制面板。

1. 在「下行Hex草稿（最多512字节）」粘贴双方核对过的**一帧完整下行**。只填 Hex 和空白，不带 `0x`、逗号或解释文字。
2. 点「校验并预览」，核对字节数和原样字节。平台不会自动补包头、LEN 或 CRC。
3. 如需核对 CRC，勾选「计算选区CRC-16/Modbus」，填从0开始、包含起止的区间，再预览。结果只供核对，不会自动加到草稿末尾。完整7E/LEN帧应选正文到CRC前一字节，不把已有CRC再算进去。
4. 在「发送目标（从现有网关选择）」选择实际连接的网关。另一个「设备网关接入名称（精确匹配）」输入框用于读取记录，不能代替发送目标选择。
5. 核对硬件、现场动作范围和完整字节，勾选「我确认报文不含清缓存指令，已核对设备与完整字节」。
6. 点「确认并提交一次发送」。在第二次确认框再核对网关、字节数和完整 Hex，确认后只提交一次。
7. 保存窗口显示的请求编号和状态。随后在「控制日志」查看对应命令详情，在「操作日志」核对提交记录。
8. 填准确网关名称，点「读取最近采集记录」，对照方向、时间、消息 ID 和 Hex。这里只查最近100条候选，没找到不代表设备没发；完整排查回到原始报文列表。

当前代码只允许核对过的单帧校时、手动操作和阈值格式，支持已识别的5/8字节校时正文；未知格式、多帧、尾随字节和CRC错误会被拒绝。两种校时正式采用哪一种、阈值上下限的含义仍待确认，能通过格式校验也不能直接当作现场操作许可。

**历史确认 ACK 的 BB02 会清硬件缓存，当前禁止实发。** 客户原始日志里存在这些包，只保留作来源核对；不要复制到发送框，也不要用功能点控制入口绕过禁令。

## 6. 发出后，什么表现算正常

| 看到的结果 | 可以说明什么 | 下一步 |
|---|---|---|
| 窗口返回编号、pending（等待下发） | 请求已排队 | 查控制日志、确认网关连接 |
| sent（已发送） | 云端已把字节写入 TCP | 对照硬件接收日志 |
| 原始快照是 write-attempt（写入尝试） | 曾准备或尝试写入 | 继续查发送状态，不能单凭它判成功 |
| 约4分钟后出现实时温度/状态 | 设备在周期回显 | 对照现场状态与报文字节 |
| unknown/timeout/提交未确认 | 结果还没核实 | 查记录和现场，不盲重发 |

手动开关没有即时返回。4分钟回显是观察窗口，不是成功倒计时；没有 commandId 或明确命令内容回显时，不能把邻近的周期包认定为某条命令的成功回应。需要“设备收到下行 + 实际动作符合预期 + 回显相符”一起核实。

## 7. 没反应时，按这个顺序查

| 现象 | 先做什么 |
|---|---|
| TCP 连不上 | 核对主机和8081端口、设备网络和出口放行，再让云端负责人查接入服务。不要改发到8080。 |
| 连上但后台没有网关 | 核对注册名称、ASCII发送方式和连接是否保持；查本轮注册/心跳时间。 |
| 网关有了，但找不到新包 | 来源选TCP、类型和状态选全部，缩小到本轮时间，搜准确网关；对照硬件发送原文。 |
| 原始报文页超时、加载失败 | 这是页面查询失败，不能当作“云端没收包”。记下时间、筛选范围和错误；本轮仍有用户反馈超时，正由开发复测。按钮若也未显示，不要反复发送硬件包试图修复页面。 |
| CRC错误、部分解析或未完成 | 对照完整字节、LEN、CRC范围和是否半包；把原文交双方核对，不让工具自动修包掩盖问题。 |
| 收到温度包，曲线没有变 | 先查业务处理状态和设备对应关系；本轮真实温度入库链路尚未验收，解码展示不等于曲线已接通。 |
| 下行一直pending | 核对选的是不是当前已注册网关，TCP是否保持；把请求编号交云端负责人查下发。 |
| 已sent但硬件没动作 | 先查硬件收到的完整Hex、目标节点和现场状态，等周期回显；不要仅因没有即时回应重复发。 |
| 提交超时，不知道发没发 | 保存草稿和编号，查操作/控制日志。同一窗口同一目标与字节重提会复用请求编号；关闭重开会成为另一请求，核实前不要这样做。 |

报问题时给这一组信息就够：**测试时间（北京时间）、网关名称、采集执行器ID/频点、方向、完整Hex、原始事件ID/连接内消息ID、下行请求编号、页面错误和现场表现**。截图遮住账号、凭据和无关人员信息。
