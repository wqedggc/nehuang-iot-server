# 涅凰智农 IoT 云平台产品说明书

> 版本：v0.5.0  
> 更新：2026-07-05  
> 口径：本说明书描述当前产品能力和已确认方向。未实现能力会明确标注，不作为已交付承诺。

## 一、产品概述

涅凰智农 IoT 云平台面向农业物联网场景，提供硬件接入、设备数据固化、管理后台、农户端展示和控制命令管理能力。

当前产品由两部分组成：

- Go HTTP 服务：Admin、Mini、MySQL、设备点位、绑定、控制命令。
- Go TCP Adapter：接收硬件网关 TCP 连接，保存原始 bytes，识别注册/心跳，并支持 pending 命令下行 Mock。

联调阶段口径：

- 下行以自定义 Hex 为主（`command_hex` 优先）；`open`/`close`/`stop` 作为兼容入口。
- 最新硬件端沟通口径中，工作数据包含三类：云端点名读取实时数据、云端下发控制/阈值类工作数据、云端周期读取累计温度记录。
- 周期累计温度记录暂按“云端每 4 小时读取一次，硬件返回前 4 小时每 5 分钟一组的累计记录”理解；若后续硬件端改为主动上报，以最终协议样例为准。
- 临时读取为“云端下发读取 hex”后，MCU 返回工作包 raw，后续由协议稳定后再做字段级解析。

网关接入模式与绑定范围以 `access_mode` 为准：

- `exclusive`：可用于单农户独享场景，绑定后默认可按网关展示该网关下全部采集执行器。
- `shared`：共享场景下，展示与可操作范围按“采集执行器/功能点授权”收敛，不展开全部采集执行器。

当前第一阶段目标是先稳定硬件接入链路：

```text
硬件网关 TCP
  -> Go gateway-adapter
  -> raw journal
  -> Go nehuang-server
  -> MySQL
  -> Admin / Mini
```

### 3.3 设备管理

当前设备主模型：

```text
设备网关
  -> 采集执行器
  -> 功能点
```

已实现：

- 按设备网关展示一级列表。
- 选中设备网关后查看采集执行器和功能点。
- 功能点搜索。
- 按绑定状态过滤功能点。
- 点位配置 API。
- 功能点编辑入口。
- 添加采集执行器入口：在已注册设备网关下创建或更新采集执行器和默认功能点，用于验证绑定、展示和下行 Hex。
- 最新口径：支持管理端在网关上下文手工建档采集执行器（频点 + 采集执行器 ID）。该建档用于协议未冻结阶段先打通业务，且不会在未确认协议前自动同步新增。

点位配置支持：

- 名称。
- 棚号。
- 单位。
- 最佳上下限。
- 运行模式。
- 是否可控。
- 轮询间隔。
- 轮询命令。
- 点位状态。
- 备注。

- 手动新增网关仍在完善；采集执行器可先在已注册设备网关下手工建档。该建档不代表真实硬件协议字段已冻结。
- Excel/CSV 批量导入未实现。

### 3.4 绑定管理

已实现：

- 查看绑定列表。
- 选择农户和已有设备网关建立绑定（历史兼容）。
- 选择农户与采集执行器建立绑定（`binding_type=collector`，共享网关默认新增口径）。
- 兼容选择农户和已有功能点建立绑定。
- 查看指定农户绑定的设备网关和功能点。
- 解绑设备。

最新产品口径下，设备关系分成两层：

```text
设备网关
  -> 采集执行器
    -> 功能点
```

其中：

- 设备网关可以由安装所在地农户拥有或管理。
- 设备网关可以被附近农户共享使用，不应默认理解为只能服务一个农户。
- 采集执行器挂在某个设备网关下。
- 农户最终使用的是绑定给自己的采集执行器及其功能点。
- 农户端展示应优先展示“绑定给该农户的采集执行器/功能点”，设备网关只作为接入网关信息展示，不应因为共享网关而把同一网关下其他农户的采集执行器全部暴露出来。

当前代码仍保留两类绑定能力（默认实现待补齐）：

```text
农户 -> 设备网关
```

和：

```text
农户 -> device_points.point_id
```

这意味着后台绑定的是已经进入系统的设备网关或功能点。“采集执行器绑定农户”将作为共享网关场景默认模型推进，避免共享网关场景下权限过宽。

### 3.5 原始报文排查

已实现：

- 原始报文查看。
- 原始报文列表。
- 原始报文详情。
- 注册、心跳、工作数据、告警、未知包五类报文分开展示。
- Adapter raw journal 由 `gateway-adapter` 独立保存。

当前排查顺序：

1. 看 `gateway-adapter` runtime log。
2. 看 raw frame journal。
3. 用 replay 工具统计报文分类。
4. 看 Go 服务 `raw_device_events` / payload 页面。

### 3.6 控制日志和控制命令

已实现：

- Mini 控制会创建异步 `control_commands`。
- Admin 可按功能点创建异步 `control_commands`。
- Admin 设备管理可对可控功能点发送自定义 Hex 下行指令，用于联调。
- Adapter 内部接口可拉取 pending、标记 sent、回写 result。
- Adapter 已支持把 pending command 的 `command_hex` 写回当前 TCP 连接，并标记 `sent`。
- Admin 控制日志展示命令来源、目标功能点/设备网关、command hex、状态、请求时间、下发时间、完成时间、网关响应和错误信息。
- 控制状态模型：`pending -> sent -> ack -> succeeded/failed/timeout`。

未完成：

- ACK 解析。
- 控制结果驱动前端实时刷新。

### 4.5 设备控制

- 真实硬件 ACK 未完成。

## 五、硬件接入说明

当前硬件侧不是调用 HTTP JSON，而是：

```text
硬件网关作为 TCP client
  -> 连接 gateway-adapter 的 IP:PORT
  -> 直接写入原始 bytes
```

Adapter 当前可识别：

| 报文 | 当前行为 |
|------|----------|
| 注册包 `FP_xxx` | 转成 register 事件 |
| 心跳包 `keepalive/keepalive message/HEARTBEAT/HB/PING/HEART` | 转成 heartbeat 事件 |
| 工作包 | 只落 raw，等待真实样例补 parser；触发方式按最新口径为云端点名读取，是否保留硬件主动上行待最终确认 |
| 告警包 | 只落 raw，等待真实样例补 parser 和去重 |
| 未知包 | 只落 raw，不中断连接 |

联调工具：

- `cmd/gateway-adapter-mock`：模拟硬件发包。
- `cmd/gateway-adapter-replay`：回放 raw journal。

详细说明见：

- `docs/gateway_adapter.md`
- `docs/hardware_protocol_current.md`

## 六、核心业务概念

### 6.1 设备层级

```text
云边网关 / LoRa 通信接入单元
  -> 采集执行器节点
    -> 功能点 / 通道
```

网关带有 `access_mode` 属性：

- `exclusive`：按网关上下文进行展示与授权。
- `shared`：仅按绑定的采集执行器/功能点授权展示。

完整硬件身份：

```text
gateway_id + frequency + device_external_id
```

功能点身份：

```text
node_id + function_type + channel_no
```

最新绑定口径：

```text
设备网关可以被多个农户共享
采集执行器必须挂在某个设备网关下
采集执行器再绑定给具体农户使用
农户端最终按采集执行器/功能点授权展示
```

因此，云端点名采集执行器时，至少需要知道：

```text
设备网关 + 采集执行器频点 + 采集执行器 ID
```

仅有“频点 + ID”不足以在云端全局定位采集执行器，必须有对应设备网关上下文。

### 6.2 功能类型

| 编号 | 类型 | 说明 |
|------|------|------|
| 1 | 温度 | 温度传感器 |
| 2 | 墒情 | 土壤湿度 |
| 3 | 限位 | 行程开关 |
| 4 | 水泵 | 水泵控制 |
| 5 | 风机 | 风机控制 |
| 6 | 继电器 | 通用继电器 |

### 6.3 硬件端最新逻辑

当前已知：

- MCU 本地做自动温控。
- MCU 每 5 分钟存一组温度。
- 最新沟通口径是云端每 4 小时读取一次累计温度记录，每 5 分钟一组；是否继续保留“硬件主动周期上报”作为兜底，需要硬件端最终确认。
- 单云边集群按最多 100 台采集执行器规划。
- 每台采集执行器有 2 秒专有时序。
- 告警包重复上报 3 次，云端需要去重。
- 控制暂定 `F0` 开、`0F` 关、`00` 停。

详细整理见：

- `docs/hardware_protocol_current.md`

## 八、常见问题

**Q: 现在硬件该怎么接云端？**  
A: 硬件网关作为 TCP client 连接 `gateway-adapter` 的 `IP:PORT`，直接写原始 bytes。第一版不是让硬件调 HTTP JSON。

**Q: 4 小时工作包是主动还是查询？**
A: 最新沟通口径倾向于云端每 4 小时点名读取一次累计记录，硬件返回 raw 工作包。此前曾按“硬件主动周期上报”理解，当前需要用最终协议文档和样例包统一口径。

**Q: 为什么工作包暂时不解析？**  
A: 硬件端文档仍有字段语义、长度、ACK/清缓存、CRC 覆盖范围等待确认点。当前先 raw 留痕，避免误解析造成错误入库。

**Q: 设备需要后台手动添加吗？**  
A: 设备网关可以通过心跳自动入库后由管理员绑定农户。采集执行器是否由设备网关上报自动入库，还是由管理员/农户在选择设备网关后填写频点和 ID 手动建档，仍需要硬件端确认。

**Q: 控制现在能真正动硬件吗？**  
A: 还不能。当前能创建异步控制命令，Adapter 下发和 MCU ACK 解析仍待实现。

## 九、管理员 / C 端 / 硬件联调使用说明入口

为减少沟通成本，提供统一使用说明入口（仅保留操作说明，不泄露实现细节）：

- 管理端帮助中心：`/admin/#help-center`
- C 端设置页按钮：「查看使用说明」跳转到 `/mini/#help-center?section=mini`
- 硬件联调流程以原始报文为中心：优先检查是否可见 register / keepalive，再看工作数据 / 告警 / 未知包。

约定统一术语：

- 设备网关
- 采集执行器
- 功能点
- 原始报文

使用说明中不会出现：

- 服务端真实地址/IP
- token 密钥
- 数据库连接串
- 内部源码路径和接口实现细节

出现问题时的建议顺序：

1. 检查原始报文是否有近 24 小时数据；
2. 检查设备网关是否有注册与 keepalive；
3. 检查控制命令 `pending` 到 `sent` 是否有 ACK/超时；
4. 检查原始报文分类（注册、心跳、工作、告警、未知）。
