# 涅凰智农 IoT 云平台产品说明书

> 版本：v0.5.0  
> 更新：2026-07-05  
> 口径：本说明书描述当前产品能力和已确认方向。未实现能力会明确标注，不作为已交付承诺。

## 一、产品概述

涅凰智农 IoT 云平台面向农业物联网场景，提供硬件接入、设备数据固化、管理后台、农户端展示和控制命令管理能力。

当前产品由两部分组成：

- Go HTTP 服务：Admin、Mini、MySQL、设备点位、绑定、控制命令。
- Go TCP Adapter：接收硬件网关 TCP 连接，保存原始 bytes，识别注册/心跳，并支持 pending 命令下行 Mock。

联调阶段口径：

- 下行以自定义 Hex 为主（`command_hex` 优先）；`open`/`close`/`stop` 作为兼容入口。
- 标准 `4 小时工作包` 作为硬件主动上报数据，不作为“云端查询即返回”的同步接口。
- 临时读取为“云端下发读取 hex”后，MCU 返回工作包 raw，后续由协议稳定后再做字段级解析。

当前第一阶段目标是先稳定硬件接入链路：

```text
硬件网关 TCP
  -> Go gateway-adapter
  -> raw journal
  -> Go nehuang-server
  -> MySQL
  -> Admin / Mini
```

```text
设备网关
  -> 采集执行器
```

已实现：

点位配置支持：

- 名称。
- 棚号。
- 单位。

- 是否可控。

- Excel/CSV 批量导入未实现。

### 3.4 绑定管理

已实现：

- 查看绑定列表。
- 选择农户和已有设备网关建立绑定。
- 兼容选择农户和已有功能点建立绑定。
- 查看指定农户绑定的设备网关和功能点。
- 解绑设备。

当前默认绑定语义：

```text
农户 -> 设备网关 -> 设备网关下所有功能点
```

兼容绑定语义：

```text
农户 -> device_points.point_id
```

这意味着后台绑定的是已经进入系统的设备网关或功能点，不是手动创建一台新硬件。

### 3.5 原始报文排查

已实现：

- 原始报文查看。
- 原始报文列表。
- 原始报文详情。
- 注册、心跳、工作数据、告警、未知包五类报文分开展示。
- Adapter raw journal 由 `gateway-adapter` 独立保存。

当前排查顺序：

1. 看 `gateway-adapter` runtime log。
2. 看 raw frame journal。
3. 用 replay 工具统计报文分类。
4. 看 Go 服务 `raw_device_events` / payload 页面。

### 3.6 控制日志和控制命令

已实现：

- Mini 控制会创建异步 `control_commands`。
- Admin 可按功能点创建异步 `control_commands`。
- Admin 设备管理可对可控功能点发送自定义 Hex 下行指令，用于联调。
- Adapter 内部接口可拉取 pending、标记 sent、回写 result。
- Adapter 已支持把 pending command 的 `command_hex` 写回当前 TCP 连接，并标记 `sent`。
- Admin 控制日志展示命令来源、目标功能点/设备网关、command hex、状态、请求时间、下发时间、完成时间、网关响应和错误信息。
- 控制状态模型：`pending -> sent -> ack -> succeeded/failed/timeout`。

未完成：

- ACK 解析。
- 控制结果驱动前端实时刷新。

## 五、硬件接入说明

当前硬件侧不是调用 HTTP JSON，而是：

```text
硬件网关作为 TCP client
  -> 连接 gateway-adapter 的 IP:PORT
  -> 直接写入原始 bytes
```

Adapter 当前可识别：

| 报文 | 当前行为 |
|------|----------|
| 注册包 `FP_xxx` | 转成 register 事件 |
| 心跳包 `keepalive/keepalive message/HEARTBEAT/HB/PING/HEART` | 转成 heartbeat 事件 |
| 工作包 | 只落 raw，等待真实样例补 parser；标准工作包固定为 MCU 主动上行 |
| 告警包 | 只落 raw，等待真实样例补 parser 和去重 |
| 未知包 | 只落 raw，不中断连接 |

联调工具：

- `cmd/gateway-adapter-mock`：模拟硬件发包。
- `cmd/gateway-adapter-replay`：回放 raw journal。

详细说明见：

- `docs/gateway_adapter.md`
- `docs/hardware_protocol_current.md`

## 六、核心业务概念

### 6.1 设备层级

```text
云边网关 / LoRa 通信接入单元
  -> 采集执行器节点
    -> 功能点 / 通道
```

完整硬件身份：

```text
gateway_id + frequency + device_external_id
```

功能点身份：

```text
node_id + function_type + channel_no
```

### 6.2 功能类型

| 编号 | 类型 | 说明 |
|------|------|------|
| 1 | 温度 | 温度传感器 |
| 2 | 墒情 | 土壤湿度 |
| 3 | 限位 | 行程开关 |
| 4 | 水泵 | 水泵控制 |
| 5 | 风机 | 风机控制 |
| 6 | 继电器 | 通用继电器 |

### 6.3 甲方最新硬件逻辑

当前已知：

- MCU 本地做自动温控。
- MCU 每 5 分钟存一组温度。
- 标准 4 小时集中上报 48 组。
- 单云边集群按最多 100 台采集执行器规划。
- 每台采集执行器有 2 秒专有时序。
- 告警包重复上报 3 次，云端需要去重。
- 控制暂定 `F0` 开、`0F` 关、`00` 停。

详细整理见：

- `docs/hardware_protocol_current.md`

## 八、常见问题

**Q: 现在硬件该怎么接云端？**  
A: 硬件网关作为 TCP client 连接 `gateway-adapter` 的 `IP:PORT`，直接写原始 bytes。第一版不是让硬件调 HTTP JSON。

**Q: 4 小时工作包是主动还是查询？**
A: 已确认是标准 4 小时工作包由 MCU 主动上报；临时读取仍保持“下发读取 hex 后返回 raw”。

**Q: 为什么工作包暂时不解析？**  
A: 甲方文档仍有字段语义、长度、ACK/清缓存、CRC 覆盖范围等待确认点。当前先 raw 留痕，避免误解析造成错误入库。

**Q: 设备需要后台手动添加吗？**  
A: 当前未实现。现在默认设备先真实上报，系统再生成主数据，后台负责配置和绑定。是否需要手动新增或批量导入需甲方确认。

**Q: 控制现在能真正动硬件吗？**  
A: 还不能。当前能创建异步控制命令，Adapter 下发和 MCU ACK 解析仍待实现。
