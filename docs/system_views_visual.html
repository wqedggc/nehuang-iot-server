涅凰智农 IoT 平台视角图

这张图把同一套系统拆成三个视角：硬件数据链路、农户看到的内容、管理员看到的内容。当前资料里“棚号”更像业务位置标签；系统底层更适合按“采集执行器功能点”存储，再由 API 按农户或棚号聚合展示。

1. 硬件与数据链路

服务端不直接理解硬件接线，服务端要能识别的是：云边网关、采集执行器、频点、功能通道和值。

服务端识别主线：FP_xxx 先按云边网关处理；devid / 设备ID 先按采集执行器处理；一行实时数据建议定位到“网关 + 频点 + 采集执行器ID + 功能通道”。

2. 农户视角看到的内容

农户不需要看硬件链路，农户需要看“我有哪些棚/场景，每个场景下有哪些可读数值和可控制设备”。

农户视角结论：可以按棚号做卡片，但数据库不建议把“棚”作为唯一主身份。更稳的是按功能点存储，接口返回时再按棚号聚合。

3. 管理员视角看到的内容

管理员需要看全局设备、绑定关系、实时状态、控制与日志。管理员视角比农户视角多“配置”和“排查链路”。

管理员视角结论：后台应该先围绕“网关在线状态、采集执行器功能点、农户绑定关系、实时/历史数据、控制日志”建设；硬件内部接线不进入后台主模型。
