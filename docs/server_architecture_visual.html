涅凰智农 IoT 云平台服务端架构图

这是服务端视角的全局架构。硬件侧只抽象成“云边/LoRa通信接入单元”，不展开内部汇聚逻辑；服务端关注两类入口：设备数据入口和客户端 HTTP 入口。MySQL 是业务唯一事实来源。

1. 全局服务端架构

设备侧通过 TCP Gateway 上云；小程序和后台通过 HTTPS REST API 进入 Go 服务端。两条入口最终都进入业务层和数据库。

边界结论：硬件侧只需要交付“服务端可识别的数据格式”和“控制命令回路”；小程序和后台怎么进入服务端，是 Go HTTP API 的内部设计，不需要硬件侧参与。

2. 服务端模块职责

这张图更偏代码结构，后续 Go 工程按这个方向拆包，不让页面直接读 JSON，也不让业务层直接依赖 TCP。

代码拆分建议：HTTP 层只处理请求和响应；Adapter 只处理设备输入转换；Service 写业务规则；Repository 只访问 MySQL；Domain 放跨模块共用的核心结构。
