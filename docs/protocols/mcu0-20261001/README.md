## 已由50帧实证验证

- 总长度 = LEN + 2；前缀为一字节7E + 一字节LEN。LEN包括末尾CRC，不包括前缀。50/50长度一致。
- CRC16/Modbus初值FFFF、多项式A001，覆盖 `wire[2:len-2]`，不覆盖7E/LEN；含Tag（存在时），末两字节低位先。50/50通过；含前缀覆盖的算法0/50通过。
- 实时36帧：正文11字节，ID2 + BB02 + HH/MM/SS3 + signed16大端温度2（除10）+ Tag1 + CRC2。本文样本温度10.8–13.2℃，负温编码仍由9/30甲方回复和单元测试支持，样本未演示负温。
- 历史3帧：正文54、42、42字节，分别15、11、11组；每组是序号1 + 温度2。线序分别01..0F、01..0B、01..0B。19点包不得抄漏最后0F。
- 状态1帧：20:28 `BB05`，正文9字节，ID2 + BB05 + 时钟3 + Tag1 + CRC2；无commandId，不证明某条命令因果执行。
- 下行10帧：两条带ID/BB00的8字节校时、两条仅HH/MM/SS/CRC的5字节校时、一次BB03手动操作、三次BB02收包确认、两次BB01阈值下行。所有长度均指正文。
- `11 39 00`按普通binary是17:57:00；工具原注释“11:57”等不能按十六进制字符串当十进制小时。21点包内部秒为01、工具收到秒为02，说明报文时钟与工具接收时刻应分别保留。
- 样本标注ID1，对应原字节0001，与大端一致；不能因此自行分配其他集群/设备数据库身份。
- Tag C0：N正常，其余状态0。C1：N正常、U=1；按PPT第9页是“关闭继电器启动”。甲方“U继电器开”表示U线圈启动，不等于卷帘开启。

## 本轮实现与离线验收

`protocol.MCU0StreamDecoder`按明确7E/LEN累积半包、分出粘包，不按正文/CRC里的7E切包。CRC无效帧保留原样与false标记；错误边界停止解析，需显式reset，不静默猜测重同步。它是本地纯解码器，尚未接入生产连接状态或自动投影。

管理员报文展示可读7E/LEN、历史/实时候选、5/8字节校时、手动/阈值下行及BB05；每TCP采集中的完整帧独立显示，残留半包标记未完成。跨采集持久重组、真实身份/时间投影仍未启用。

另修复明确TCP留存缺陷：Read同时返回n>0与EOF时先journal保存字节，再结束连接。

验收：50帧每个拆包位置；整段按1/2/7/13/64字节与一次粘包回放；CRC坏帧、正文含7E、非法长度、显式reset；36实时+3历史+1状态；50帧管理员展示、残留半包与坏CRC无温度投影；EOF尾字节先保存。运行 `go test ./internal/gatewayadapter/... ./internal/protocolsummary ./internal/service`。

自动校时、BB02发送/清缓存、真实命令下发均保持关闭；本轮不部署、不合并。
