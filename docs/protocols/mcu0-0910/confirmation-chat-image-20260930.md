## 最新确认

1. 对包头再加“包长的识别字段”表示同意，统一加入。结合此前0x7E回复，方向为0x7E包头加包长；字段宽度、端序、长度是否包含包头/长度字段/CRC、转义及CRC覆盖边界均未答复。“7E+length+原报文+CRC”仍不是云端可自定的生产协议。
2. 回复解释5/10…60分钟正好12组；与前次最新整点样本、5分钟倒排的逻辑窗口并不替代实际数组/序号映射。05…60只描述12个时点，60应在真实样例中核对整点表示方式；不能编码非法minute=60或推定线序。
3. 原话“先不清吧”“清缓存这个逻辑指令，你先给我留着”。**当前云端默认不发清缓存/BB02，不自动清缓存**；保留纯函数和后续手动指令能力设计，实际发送范围需单独明确。此前硬件收到BB02会清缓存的语义仍可保留，但不因此自动发送。
4. 希望留“虚拟对话框，就像那个com工具那样，直接让我能从云端发任意报文到下行”，用于采集试验，避免所有变化都进业务逻辑。用户当时询问可行性，后来授权继续本地联调工作；本轮先交付可回退的只读/预览增量，不创建任意报文实发入口。
