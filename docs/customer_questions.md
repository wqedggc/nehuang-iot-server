# 涅凰智农待甲方确认问题

> 更新日期：2026-07-05  
> 口径：本文件只记录需要甲方明确答复的问题，用于硬件联调、后台产品口径和交付边界确认。

## 已确认（按联调阶段口径）

1. 标准 4 小时工作包（48 组）为硬件端主动上报，不走“查询请求即返回历史记录”的模式。
2. 临时读取场景为云端下发读取 hex 后，MCU 返回 raw 工作包；标准工作包字段含义、ACK、清缓存仍待确认。

## 一、后台产品口径

1. 后台展示名是否统一采用以下口径：
   - 设备网关：连接云端 TCP Adapter 的网关设备。
   - 采集执行器：设备网关下挂的具体采集/执行硬件。
   - 功能点：采集执行器上的温度、墒情、限位、继电器等通道。
   - 原始报文：硬件上报到云端后未解析或待排查的 raw bytes。
2. 农户和设备的关系是否按“农户绑定设备网关”处理：
   - 一个农户可以绑定多个设备网关。
   - 一个设备网关同一时间只归属一个农户。
3. 是否存在一个设备网关被多个农户共同查看或共同控制的场景。
4. 是否需要保留“按单个功能点授权给农户”的精细权限；如果需要，哪些场景会用到。
5. Dashboard 的主要用途是运营总览，还是硬件联调看板。
6. Dashboard 设备网关在线口径可按 `keepalive` 心跳判断；采集执行器/功能点业务离线是否需要按 4 小时工作包周期另设口径。

## 二、设备注册和绑定

1. 设备网关注册报文是否会携带农户编号、安装编号或绑定码。
2. 如果注册报文携带绑定码，云端是否可以自动把设备网关绑定到对应农户。
3. 如果注册报文不携带绑定码，后台是否只允许管理员手动绑定。
4. 如果后续硬件侧将“设备网关”和“采集执行器”两个层级二合一，云端是否仍保留默认采集执行器节点，还是在产品展示中合并为一个层级。
5. 功能点是否需要 `channel_no` 才能唯一定位。

## 三、上行工作包和告警包

1. 请提供至少 3 条真实工作包 raw hex：
   - 正常温度包。
   - 多组 4 小时缓存包。
   - 边界温度或异常状态包。
2. 工作包中每个字段的字节位置、长度、大小端和缩放比例是什么。
3. 温度字段是否为有符号 16 位整数，是否需要除以 10。
4. 告警包最终格式是什么。
5. 同一告警重复 3 次时，云端按什么字段去重。
6. 告警解除是否有单独报文；如果没有，云端如何判断告警恢复。

## 四、下行控制和 ACK

1. 控制命令的真实目标是：
   - 功能点。
   - 采集执行器。
   - 设备网关整体。
2. 下行命令完整 bytes 格式是什么，包括包头、目标地址、命令字、CRC。
3. MCU 收到命令后的 ACK 报文格式是什么。
4. `AA AA BB ZZ` 在不同场景下的准确含义是什么：
   - ACK。
   - 执行完成。
   - 清缓存。
   - 其他语义。
5. 命令发送后多长时间没有 ACK 算超时。
6. 命令失败时 MCU 是否会返回失败原因。
7. 云端读取 4 小时缓存成功后，应该用什么命令通知 MCU 清缓存。

## 五、时隙和网关职责

1. 2 秒时隙由谁维护：
   - MCU。
   - 硬件网关。
   - 云端 Adapter。
2. 硬件网关是否可以缓存云端下发命令，并在对应采集执行器窗口到达时转发。
3. 如果硬件网关不能缓存命令，云端如何知道某个采集执行器当前处于可下发窗口。
4. 硬件网关和 MCU 是否有统一的同步包或广播起点。
5. 网络延迟超过时隙窗口时，硬件侧期望如何处理：
   - 丢弃本次命令。
   - 下一窗口重试。
   - 返回超时/失败。
6. 是否允许 MCU 主动轮询云端 pending command；如果允许，轮询报文格式是什么。

## 六、上线联调

1. 真实硬件联调前，是否需要提供白名单 IP。
2. 联调失败时甲方能提供哪些侧的日志：
   - 硬件网关连接日志。
   - MCU 发包日志。
   - 原始 bytes dump。
