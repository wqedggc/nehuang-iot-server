# 联调报文窗口：范围与复用路径

目标为一期硬件联调后台。来源：[已视觉核对的甲方截图](protocols/mcu0-0910/confirmation-chat-image-20260930.md)。业务解析与原始收发通道分开；不实现MCU0无线时隙。

## 本轮已实现的可验收增量

管理后台“原始报文排查”→“报文调试预览”：

- 原始Hex草稿校验，显示字节数，最多512字节；只接受Hex与空白，拒绝奇数长度、0x/逗号/其他字符。
- CRC默认关闭。操作者明确输入从0开始且包含起止的区间后，可计算CRC-16/Modbus，FFFF/A001，显示低字节先结果；不会附加CRC、修改原稿、移除0x7E、补包头或推测包长。
- 复用已有管理员鉴权`GET /api/v1/admin/payload-events`与TCP原始留存；读取最近100条关键词候选，再精确匹配网关名和source_type=1。只呈现有权限API返回的数据；非完整历史查询。展示时间、message_id及Hex，详细direction/write-attempt仍查看原始快照。
- 日志使用textContent，不能把报文变成HTML；关闭重开后旧请求不覆盖新窗口；没有自动轮询或自动重发。
- **新窗口没有发送按钮/API，不发送任意报文，不发送BB02、不清缓存、不关联周期回显为commandId成功。** 这是只读与草稿预览，不称完整COM发送功能已完成。

## 已有路径与后续最小发送设计

已有功能点Hex下发：Admin创建control_commands → Adapter轮询pending → outbound journal → TCP write → sent状态；原始报文保留capture/message身份。现有入口绑定功能点，不能直接称任意网关调试窗口。

若明确批准后续实发范围，复用上述队列/journal/日志，另增加管理员调试命令入口：选择数据库确认的网关与设备/集群身份，校验目标、Hex、512字节上限，按目标限制频率；预览确认后仅发送一次，无自动重发。默认不自动组CRC，包长/CRC范围明确后才开放可选构造。清缓存功能默认禁用；任意未知报文无法仅靠字节搜索可靠证明无危险副作用，不能以“检查某字节不是02”当安全保证。

必须区分排队、尝试写、已写、结果未确认。周期温度回显仅为观察。使用已有合法管理员鉴权，不绕认证，不向硬件方直接新建账号/凭据或授予权限。未知帧结构不先固化到业务控制逻辑。

预览增量已完成；完整发送增量粗估另需半天至一天本地实现与回归，真实联调验收另计，取决于目标和协议答案。本次不执行服务器部署。

## 2026-09-30 管理员单次发送

原始报文页 → 报文调试窗口。选择现有网关，预览完整 Hex（1–512 字节），勾选不清缓存并二次确认。CRC 仅计算所选范围用于预览，不自动附加；包头、包长与转义由操作人按最终协议填入。已知 BB02 结构被拦截，未知封装不得凭此认为已完成协议验证。

POST `/api/v1/admin/raw-debug/commands` 要求管理员身份、精确 gateway_id/name 和稳定 request_id；命令与操作审计同事务写入。每网关至少间隔两秒。同请求重提返回已有命令，不自动重试。关闭重开窗口表示明确发起另一请求。

Adapter 先持久领取再写 TCP：领取回应丢失不发送；领取后崩溃不会自动再发，状态 unknown，需人工核对。TCP 写入成功为 sent，不等于设备执行。无即时 ACK 的手动命令不自动超时或重发；周期温度不归因到 command_id。

收发日志查询原始 TCP `include_payload=1`，显示 direction/capture_kind 与原样 hex；write-attempt 不证明成功。下行快照只留存，不投影为遥测。部署和测试不会提交真实硬件命令。
