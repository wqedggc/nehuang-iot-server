# 报文调试窗口：当前入口与维护边界

更新：2026-10-02。客户操作步骤见 [硬件接云和报文联调说明](product_manual.md#5-在哪里手动发下行测试报文)。本文件供开发维护使用，替代此前“窗口没有发送能力”的旧口径。

入口：`/admin/#payload-events`，「原始报文排查」列表上方「报文调试窗口」。原始列表请求成功后才渲染该按钮；当前用户会话出现约10.75秒超时，导致入口也不显示，开发任务正在分离入口。本文不宣称已修复或已完成线上UI验收。

## 当前代码实现

- Hex草稿1–512字节，只接受Hex和空白；拒绝奇数长度、0x、逗号等。CRC计算需主动选择包含起止的区间，仅预览，不修改或自动补齐原稿。
- 单次发送从已有网关选择目标，二次确认目标/字节，并要求不清缓存确认。只放行已核对单帧5/8字节校时、9字节手动正文、12字节阈值正文与对应7E/LEN封装；CRC、时钟、单帧长度检查失败拒绝。BB02禁止，未知格式、多帧和尾随字节拒绝。格式校验不证明阈值语义或现场动作允许。
- `POST /api/v1/admin/raw-debug/commands` 保留管理员鉴权、精确gateway_id/name、稳定request_id及操作审计。每网关至少间隔两秒；同请求重提返回已有命令，不自动重发。同窗口换目标或字节要求关闭重开，核实结果前不能把关闭重开当重试。
- Adapter领取并留存后尝试TCP写入。pending、write-attempt、sent、unknown分别表示排队、尝试、已写TCP和结果未知；均不能替代真实设备动作确认。无即时手动ACK，不把4分钟回显关联为commandId成功，不自动重发或清缓存。
- 「读取最近采集记录」按输入网关查最近100条候选后精确匹配TCP来源，含原始payload，展示时间、消息ID、direction和capture_kind。它不是完整历史检索；记录详情仍需打开原始快照。
- 关闭重开后的旧异步响应不覆盖新窗口；报文字节用textContent呈现；无自动轮询。
